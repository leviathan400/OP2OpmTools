# OP2OpmTools

![Screenshot](https://images.outpostuniverse.org/OP2OpmTools.png)

## What is it?

Open an OP2MissionEditor `.opm` json file and convert it to **C++ code** or to a complete **OP2Lua mission**.

The OP2MissionEditor is very good for object placement (vehicles, buildings and beacons). We can use it to setup our objects for our Outpost 2 dll mission. We can then use OP2OpmTools to convert the object placement data from the `.opm` file into either:

- **C++ code** - an `InitProc()` to paste into a hand-built Outpost 2 mission dll project, or
- **An OP2Lua mission** - the two `.lua` script files ([OP2Lua](https://github.com/leviathan400/OP2Lua) missions need no compiler), or
- **A text report** of the contents of the `.opm`.

The [OP2MissionEditor](https://github.com/leviathan400/OP2MissionEditor) saves its missions in a json file format with the `.opm` file extension.

## Export buttons

| Button | Output |
|---|---|
| **Export C++** | `mission.cpp` - a `TethysGame::CreateUnit(...)` `InitProc()` for a C++ dll project |
| **Export Lua** | `<Name>.lua` + `<Name>.placement.lua` - a runnable OP2Lua mission (see below) |
| **Export Report** | `mission.txt` - a human-readable summary of the `.opm` |

## Sample Output - C++
Here's an example of the C++ code generated from an .opm file:

```cpp
// Generated by OP2OpmTools
Export int InitProc()
{
    // Player 0 (Blue)
    Player[0].GoPlymouth();
    Player[0].SetColorNumber(0);
    
    Unit x;
    
    // Create units
    // CargoTruck at position 13, 8, facing East
    TethysGame::CreateUnit(x, mapCargoTruck, LOCATION(13 + 31, 8 - 1), 0, mapNone, 0);
    x.DoSetLights(1);
    
    // Tiger Microwave at position 13, 11, facing East
    TethysGame::CreateUnit(x, mapTiger, LOCATION(13 + 31, 11 - 1), 0, mapMicrowave, 0);
    x.DoSetLights(1);
    
    // Panther Supernova at position 19, 11, facing West
    TethysGame::CreateUnit(x, mapPanther, LOCATION(19 + 31, 11 - 1), 0, mapSupernova, 4);
    x.DoSetLights(1);
    
    // CommandCenter at position 97, 35
    TethysGame::CreateUnit(x, mapCommandCenter, LOCATION(97 + 31, 35 - 1), 0, mapNone, 0);
    
    // Agridome at position 104, 35
    TethysGame::CreateUnit(x, mapAgridome, LOCATION(104 + 31, 35 - 1), 0, mapNone, 0);
    
    // Create walls and tubes
    CreateTubeOrWallLine(100 + 31, 35 - 1, 101 + 31, 35 - 1, mapTube);
    TethysGame::CreateWallOrTube(102 + 31, 35 - 1, 0, mapTube);
    
    return 1; // return 1 if OK; 0 on failure
}
```

The generated code is ready to paste directly into your Outpost 2 mission project and will recreate all the units, buildings, walls, tubes, and beacons that were placed in the OP2MissionEditor.

## Sample Output - Lua (OP2Lua mission)

**Export Lua** writes a complete [OP2Lua](https://github.com/leviathan400/OP2Lua) mission - **two `.lua` files** that share a base name (taken from the file name you choose):

- **`<Name>.placement.lua`** - the layout (players, units, beacons, walls, markers) converted straight from the `.opm`.
- **`<Name>.lua`** - a starter mission-logic script (an `on_init` with win/lose conditions wired to the players found in the `.opm`).

Drop both next to an OP2Lua stub dll named `<Name>.dll` and the mission runs - no compiler needed.

> **Coordinates:** unlike the C++ export (which bakes the `+ 31 / - 1` offset into `LOCATION(...)`), the Lua files use the raw `.opm` editor coordinates - the in-game status-bar coords - because the OP2Lua runtime applies that engine offset itself. So what you placed in the editor is what you write here.

#### `MyMission.placement.lua`
```lua
-- MyMission.placement.lua  -  generated by OP2OpmTools v0.3.1 from eden01.map
-- Coordinates are the in-game status-bar coords stored in the .opm (no offset applied).
return {
  name = "MyMission", map = "eden01.map", tech = "MULTITEK.TXT", type = "Colony",
  max_tech = 12, players_count = 2,

  players = {
    [1] = {
      colony = "Eden", human = true, color = "Blue",
      resources = { common_ore = 5000, rare_ore = 2000, food = 5000, kids = 10, workers = 20, scientists = 12, tech_level = 12, morale = "Good" },
      center_view = { 14, 56 },
    },
    [2] = {
      colony = "Plymouth", human = false, color = "Red", bot = "Balanced",
      resources = { common_ore = 8000, rare_ore = 4000, food = 8000, kids = 30, workers = 40, scientists = 20, tech_level = 12 },
    },
  },
  units = {
    { type = "CommandCenter", player = 1, at = { 10, 57 } },
    { type = "Agridome", player = 1, at = { 13, 57 } },
    { type = "Tokamak", player = 1, at = { 13, 59 } },
    { type = "Tiger", player = 1, at = { 14, 54 }, weapon = "ThorsHammer" },
    { type = "CargoTruck", player = 1, at = { 11, 55 }, cargo = "RareMetal", amount = 1000 },

    { type = "CommandCenter", player = 2, at = { 56, 40 } },
    { type = "Tokamak", player = 2, at = { 59, 40 } },
    { type = "GuardPost", player = 2, at = { 54, 38 }, weapon = "RPG" },
  },
  beacons = {
    { type = "MiningBeacon", ore = "Common", at = { 8, 58 } },
  },
  walls = {
    { type = "Wall", at = { 18, 56 } },
    { type = "Wall", at = { 18, 57 } },
  },
  -- regions are not stored in the .opm; add named rectangles { x1, y1, x2, y2 }
  -- or points { x, y } that your mission script references.
  regions = {},
  markers = {},
}
```

#### `MyMission.lua`
```lua
-- MyMission.lua  -  MyMission  -  mission logic.
-- Generated by OP2OpmTools v0.3.1 from eden01.map.
-- The .opm has no mission logic, so this is a starter script - edit freely. See docs/API.md.

function on_init()
  game.message("MyMission: destroy the enemy Command Center!")
  game.morale_steady()   -- keep morale stable so it's about the fight, not colony micro

  -- WIN: the enemy has no Command Center left.
  when(function() return not players[2]:owns_any("CommandCenter") end, function()
    game.message("Enemy base destroyed - mission accomplished!")
    mission.win()
  end)

  -- LOSE: your Command Center is gone.
  when(function() return not players[1]:owns_any("CommandCenter") end, function()
    game.message("Your Command Center is destroyed. Mission failed.")
    mission.lose()
  end)
end
```

The win/lose conditions only reference a `:owns_any("CommandCenter")` check when that player actually has a Command Center in the `.opm`, so the generated mission never fires on an impossible condition. Edit `<Name>.lua` to flesh out the rest of your mission logic.
